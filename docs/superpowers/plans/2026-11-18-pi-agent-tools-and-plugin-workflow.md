# Pi Agent 与 Harness 实施顺序

本顺序依据已确认的产品方向文档 [`2026-11-18-pi-personal-agent-product-direction.md`](../specs/2026-11-18-pi-personal-agent-product-direction.md)。它取代早期计划中“先完成确定性报告流程”的顺序。沿用工作区中已有的修改和可复核证据，不以计划或 Spike 作为继续实现的总门槛。

## 已确认的产品决策

- Pi 是 Agent 底座，只复用符合产品需求的 Pi 能力，不把系统改造成可替换任意 Agent 引擎的平台。
- 借鉴 DeepSeek Harness 的插件管理和 Agent 创建插件流程，不整体照搬其运行时、执行内核或权限实现。
- Harness 负责权限、任务状态、隔离、运行日志和可靠性。插件只通过 Harness 的受控能力接口工作。
- 首版推进 Agent 为用户创建、测试和管理本地插件的闭环。任意第三方插件安装和公开市场后置。
- Agent 创建或更新的插件先作为草稿，经用户确认后启用。插件开发与测试记录保存在本地，Langfuse 用于改进 Harness。
- 普通插件按受限 Worker 运行，不继承宿主的全部权限。

## 推进顺序

1. **Pi 驱动的对话与工具：** 使用 Pi Agent Core 和 Pi AI 完成真实模型对话与工具循环。桌面 Runtime 作为 Harness 负责工具准入、权限检查、任务状态、隔离边界、脱敏日志和恢复。当前纵向切片开放用户选择工作区后的受限只读能力。代码与本地模拟服务已有验证，真实 Provider 和桌面人工验收按清单记录。
2. **产品维护 Skills 启停：** 先交付内置 Skills 的本机启停、Pi system prompt 注入、状态持久化和 transcript 配置隔离。按 [Skills 设计与验收清单](2026-11-20-product-maintained-skills/) 实现。
3. **权限受控的 MCP：** 随后实现用户授权的 MCP 连接和工具注册。先落实连接/能力授权、受限 Worker 和日志，再开放给 Pi。
4. **Agent 创建的本地插件：** 按 [本地插件设计与清单](2026-11-20-local-plugin-workflow/) 推进。 创建或更新时生成未启用草稿，在受限 Worker 中测试，在本地保留开发和测试记录，向用户展示改动与申请能力，并在用户确认后启用。更新后重新确认，提供启用、停用和管理操作。
5. **后续产品切片：** 逐步扩展文档处理、网页调研、持久任务与恢复、企业微信、记忆、定时事项和数据维护。局部风险按具体能力处理，不阻断无关功能交付。

## 技术与产品边界

Pi 是产品 Agent 底座。DeepSeek Harness 仅作为插件工作流参考。普通插件不继承宿主权限。首版不提供任意第三方插件安装或公开市场。
