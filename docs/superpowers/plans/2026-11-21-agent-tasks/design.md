# 可跟踪 Agent 任务设计

## 调研

可复用 SQLite、Pi 模型流、授权目录只读工具和文档来源、主进程模型密钥、任务状态与日志呈现。当前 TaskRunner 负责固定本地报告，审批和状态已持久化。缺少从目标生成步骤的 Pi 任务、步骤结果、实时控制与可恢复执行。

## 改动与接入

1. Agent 任务作为独立记录使用同一 SQLite。记录任务目标、模型配置 revision、可用工作区身份、状态和检查点。保留现有本地报告流程。
2. 桌面「Agent 任务」发送目标后立即返回任务。Pi 先生成 1–4 个有界步骤，然后逐个读取授权目录并执行。每步保存结果、来源和工具摘要。最终交付为任务详情内的文字报告，可复制。工作区文件交付仍通过既有对话产物确认。
3. 每个任务独立运行且同一时刻只运行一个 Agent 任务，绑定开始时的 Profile 配置和可用目录。禁用工作区写入、MCP 和插件。模型调用、工具次数和整步耗时设限。运行暂停/取消立即持久化，再打断当前模型调用。撤销授权或改变模型配置时中止提交。
4. 进程重启令未完成的运行变为「已中断」。用户继续时重新核验配置后从下一未提交步骤开始。已完成的步骤不重复。重试中的模型费用仍取决于服务端。
5. 任务列表突出状态、当前步骤和对应动作，展开显示结果和来源。桌面启动前说明外发范围。主进程只给启动和继续注入当前绑定的模型密钥。

## 风险

步骤中断可能消耗了模型额度，Harness 只保证已提交检查点不重复。步骤无外部写入。已撤销目录的授权和已修改模型不能被旧任务隐式继承。任务查询与控制须在模型等待期间可用。
