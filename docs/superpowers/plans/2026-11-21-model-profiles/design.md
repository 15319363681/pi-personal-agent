# 多模型配置管理设计

日期为 2026-11-21。实现用户确认的多模型服务、自定义兼容端点与本机密钥管理流程。人工操作验收本轮暂缓，以离线测试为主。

## 调研与复用

- ModelSettings 已按 id 保存配置数组，支持 Chat Completions 与 Responses 兼容协议，密钥由 Electron main 的 CredentialVault 加密保存。
- Runtime 已通过 Pi 执行真实模型及工具调用，配置变化通过上下文指纹隔离 transcript，UI 历史保留。
- main bridge 已将凭据更新、连接测试和模型请求串行处理，覆盖提交不确定后的引用核对。
- 缺失完整的多配置选择、新建、命名、删除及当前配置持久化，UI 当前固定读取列表第一项，chat.send 默认使用 default。
- 配置 JSON 写入当前缺少串行和原子替换，同时保存可能丢失变更。

## 改动与接入

### M1 配置存储

保留旧数组格式，增加可选 name 与 supportsImages 字段。新旧配置共用相同存储，串行变更后在同目录创建临时文件并 rename。新增 remove，返回实际删除记录。读取保持兼容原有仅有 id 的配置。

### M2 当前配置与凭据

当前配置 id 保存到 Runtime SQLite meta，settings.get 返回 activeSettingId。旧数据优先 default，其次第一项。settings.activate 明确切换当前配置。settings.remove 需要 confirm=true，删除当前项时选择剩余第一项或空状态。chat.send 和 settings.test 未指定 id 时使用当前项。main bridge 解析同一当前配置，只获取该配置的本机密钥，删除配置提交成功后清理对应密文。删除提交结果不明时回查设置，保留仍在引用或状态不明的凭据。

### M3 桌面交互

新增 ModelSettingsPanel，提供配置选择、命名、新建、保存、连接测试、设为当前和确认删除。对话发送区展示当前模型。编辑草稿和已生效配置分离，轮询刷新保留未保存输入，切换草稿有明确放弃提示。每次连接测试绑定已保存配置快照，过期响应不得解锁其他配置。新建和删除展示明确状态，加载中有反馈，错误保留可操作提示，表单具有标签和键盘焦点。

## 推进顺序

M1 存储与并发，M2 Runtime 与 main 接入，M3 桌面管理，V1 针对性及集成回归，V2 Electron DOM，V3 全量测试与构建，V4 独立审查。

## 风险

- 密钥密文与配置文件跨存储提交存在断连窗口，复用 main bridge 的提交核对，无法确认时保留密文以便恢复。
- 兼容服务能力由用户指定，图片能力声明会为后续图片资料切片提供入口，本轮仍以文本对话验证。
- 真实服务可用性与费用需要用户实际账号验证，自动测试使用本机 HTTP/SSE 服务。
- 配置删除确认只删除应用内配置与对应凭据。
