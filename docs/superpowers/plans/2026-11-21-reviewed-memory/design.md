# 审核个人记忆设计

## 调研

可复用 SQLite、现有 JSON 记忆格式、Pi 工具接入、桌面 IPC 与受限日志。旧 MemoryStore 支持搜索和墓碑，运行时尚未把审核后的记忆提供给模型。缺少待审核状态、版本确认、编辑、删除和桌面入口。

## 改动与接入

1. 在 SQLite 保存待审核和已审核记忆，每条有来源、revision、创建及更新时间。首次导入有效旧 JSON 记录作为待审核，同一个旧 ID 只导入一次。现有 MemoryStore 供旧调用兼容。
2. 新增 propose、approve、update、delete、list。批准与删除必须确认具体 id/revision。编辑会产生待审核的新版本，保留旧审核版本供用户决定是否替换。删除后停止模型使用。模型只有提议工具，用户在桌面审核。
3. 普通对话与任务共用已审核记忆。系统提示以 JSON 数据携带，限定总长度，记录使用的记忆 ID。记忆变更使后续对话切换上下文，运行中的对话拒绝提交旧版本结果。任务绑定启动时记忆版本，变更后暂停旧版本提交。网页调研继续只接收公开查询和搜索资料。
4. 桌面提供审核队列、来源、编辑和内容确认。失效 revision 要刷新，失败保留草稿。表单标签、键盘焦点、状态反馈与小窗口布局一起验证。

## 推进顺序

先存储与迁移，再接入 Pi 和版本边界，再做桌面审核，最后针对性、Electron、全量回归和独立审查。

## 风险

审核意味着允许模型服务收到该条偏好。界面明确说明外发范围。删除立即影响后续调用，服务端既有请求仍可能已收到旧文本。诊断只记录 ID 和计数。
