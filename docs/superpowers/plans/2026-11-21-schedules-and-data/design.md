# 提醒、周期任务与数据维护设计

## 调研

复用 Agent 任务、SQLite 事务、主进程密钥保险库和系统文件选择器。旧 BackupManager 只备份数据库，恢复会停留在 recovery_mode。缺少计划实例排重、提醒读取、计划任务 UI、产品备份和恢复核对。

## 提醒与周期任务

1. SQLite 计划表保存内容、首次时间、周期、启用状态和模型/工作区绑定。用户在表单确认后保存，支持暂停、启用、确认删除。提醒可单次或重复，周期 Agent 任务共用现有只读步骤执行能力。
2. 主进程每 5 秒发起一次 tick，SQLite 原子领取到期实例并推进下次时间。离线遗漏合并为一次，界面显示实际计划时间。任务实例先标记 executing 再调用 Agent，重启后该实例标记 interrupted，用户可以从任务列表核对，自动重放由新的周期实例驱动。
3. 任务只在原模型 revision 和目录身份匹配时执行，否则保留失败原因。运行中的同类任务产生明确 busy 状态。密钥由主进程按计划绑定配置注入。提醒在桌面列表持久保存，并尝试系统通知，通知失败不丢提醒。
4. 桌面退出期间暂停计时，重新启动后处理最近一期到期实例。提醒操作不会主动发送企业微信消息。

## 备份、恢复与诊断

1. 创建 .pi-backup JSON 包，包含一致性 SQLite 快照、非秘密模型配置、格式版本和 SHA256。数据库含会话、记忆、任务、计划、插件版本与本地测试记录。工作区文件由用户另行保管，密钥保险库独立保留。
2. 文件选择器授权具体备份位置与恢复来源。恢复预览绑定文件摘要与限时 token，二次确认后关闭渠道和运行时。暂存目录校验数据库完整性，安装前保存当前 runtime 目录作为回滚副本。原子目录切换配合 journal，重启可核对中断的替换。
3. 恢复后清除目录授权、连接凭据引用和模型上下文，暂停计划，停用插件与 MCP 工具，保留审核记忆及历史结果。用户重新填写密钥并授权后即可继续使用。恢复核对完成清除 recovery_mode，避免永久冻结。
4. 诊断导出仅包含版本、平台、状态计数、错误代码和受限日志，限制大小。会话正文、记忆、文档、任务目标、密钥和端点均不进入诊断。

## 桌面交互

提醒与维护渐进展开。主操作集中在新建计划、读取提醒、备份。恢复先展示影响和来源再确认。键盘焦点、忙碌状态、失败保留输入及 900px 布局一起验证。

## 推进顺序

先计划持久化与领取，再主进程触发与桌面操作，再备份包、恢复 journal 和诊断，最后故障注入、Electron、全量与独立审查。

## 风险

系统通知受操作系统设置影响，列表记录作为可查证结果。备份包含个人正文，需要用户保管。恢复在当前机器停用旧密钥关联，防止备份中的端点继承本机密钥。跨机器重新配置密钥与目录。远程服务、系统时间变化和断电场景以可重现夹具验证后记录仍需实测的边界。
