# 企业微信本人单聊设计

## 调研

复用官方 @wecom/aibot-node-sdk 1.0.7 的认证、心跳、回执与指数退避重连，复用桌面密钥保险库、SQLite、Pi 对话、审核记忆和 Agent 任务。缺少本人白名单、独立历史、持久化消息排重和桌面连接设置。

官方参考 https://github.com/WecomTeam/aibot-node-sdk 。本地安装后的 README 与类型定义已核对单聊 chattype、from.userid、aibotid、message.text 和 replyStream。

## 改动与接入

1. 主进程维护 SDK 连接，固定官方 WSS 地址。独立加密目录保存 secret，公开配置只含 botId、本人 userid 和凭据引用。保存配置先断开，连接由用户主动发起。会话内由 SDK 自动重连，认证重试有上限，连接状态与失败码可见。
2. 只接受匹配 botId、本人 userid 的 single 文本消息，拒绝群聊及其他身份。SQLite 原子 claim msgid，断线与重启后重复回调不会再次执行。处理后保存回复与投递状态，失败不自动重放模型或任务。
3. 桌面和渠道共用活动模型、授权目录、审核记忆、任务状态。渠道会话按 botId 与 userid 的散列独立保存，桌面 Renderer 不能调用渠道内部 RPC。更换本人或机器人切换渠道历史。
4. 文本直接调用 Pi。使用 /任务 目标 创建共享任务，/任务列表 或 /任务 ID 查看，/暂停 ID、/继续 ID、/取消 ID 操作。所有回复只使用当前收到的回调，桌面内可以查看独立渠道记录。远程文件消息处理后续扩展。
5. 桌面设置渐进展开，提供密钥保留、本人确认、连接/断开、重试和记录状态。主进程退出关闭连接。

## 推进顺序

先渠道存储与隔离，再 SDK 连接、凭据和受限回复，再 UI，最后协议夹具、真实 Electron 与全量验证。

## 风险

实际企业管理员需要配置智能机器人长连接和获取本人 userid。离线夹具无法证明真实企业账号连通。回复回执超时表示投递结果未知，界面提示重发可能产生重复，保留本地结果供查看。桌面退出后不提供常驻渠道服务。
