# Pi Personal Agent 产品质量与工作会话交接标准

日期：2026-11-17  
适用项目：`D:\Atry`  
目的：把“做成完整、可信赖、好用且有品质的产品”转化为工作会话可执行、用户可验收的标准。本文件是产品方向和质量门槛，不代表当前产品已达到这些标准。

## 产品目标

Pi Personal Agent 是 Windows 本机优先的个人任务 Agent。用户应该能配置并验证模型，描述希望完成的工作，检查 Agent 提出的计划和权限，批准后让它在限定工作区内执行，查看进度与产物，并在失败或中断后理解如何处理。

目标不是“界面看起来像 Agent”，而是用户从第一次启动到一次真实、受控、可解释的任务完成，整个过程中都知道系统状态、费用与权限边界，并能决定继续、暂停、取消或修复。

## 产品原则

1. **真实能力优先。** 只有真实连通且被当前运行路径使用的能力才显示为可用；设置保存、测试连接、模型回复、任务完成分别展示真实结果，不用静态文本冒充成功。
2. **用户掌控副作用。** 模型调用前显示所选模型和可能产生费用的提示；文件写入、发送、删除等动作受权限和审批约束。取消、超时或恢复状态不明确时，显示真实的不确定状态。
3. **状态可理解、可恢复。** 对话、任务、运行步骤、预算、产物、通知分开表达。错误说明发生了什么、影响范围和下一步，提供重试/编辑/查看日志等适当操作。
4. **动作出现在上下文中。** 当前对象的主要操作跟随对象和状态；破坏性操作收进次级菜单并确认。每个按钮都有明确名称、可预期结果、禁用/执行中/成功/失败状态。
5. **默认克制、细节精致。** 用排版、对齐、留白、稳定的组件尺寸和轻微层次建立质感。动效、阴影、插图只帮助理解、定位或反馈，不替代信息架构。
6. **先可用，再打磨，再迭代。** 自动化测试用于验证代码契约；它不能代替用户实际点击、判断信息是否易懂和流程是否顺手。每轮提供可运行构建、手动验收步骤和脱敏日志，再根据用户反馈修正。

## 建议的信息架构

采用紧凑的桌面工作台，不再把所有内容堆成一个长页面：

- **左侧主导航：** 工作台/新对话、任务、历史记录；记忆和设置作为稳定的次级入口。避免为尚未实现的功能预留空页面。
- **中央主工作区：** 当前对话和任务主流程。底部固定输入区；发送后明确区分“普通对话”和“创建任务”，不要悄悄把每句话都变成任务。
- **右侧上下文面板：** 仅在当前任务相关时展示任务目标、模型、权限范围、预算、进度、产物和通知状态；可折叠，窗口变窄时改为侧栏/抽屉。
- **首启与模型配置：** 尚无可用模型时，引导用户完成 Provider、模型、端点和密钥设置，并先执行独立的“测试连接”。连接失败时保留输入并给出可操作错误，不允许进入一个看似可聊、实际只会返回固定文本的假状态。
- **诊断日志：** 在帮助/诊断入口查看或打开日志，不把完整本机路径永久塞在主标题区。日志脱敏，并以关联 ID 对应界面中的错误。

建议的主流程：首次配置模型并测试连接 → 新建对话 → 描述目标 → Agent 返回可审阅的计划、权限与费用信息 → 用户批准 → 展示执行进度与可控操作 → 检查产物和验收结果 → 展示通知结果 → 可继续追问或修订。

## 视觉方向

视觉主张：**安静、清晰、可信赖的个人工作台**。采用中性浅色作为首版默认主题，深色主题可作为后续增强；以清晰的字级、间距和少量表面层次建立组织感。使用一个主操作色，成功、警告、危险等颜色只用于对应状态，并保持文字和控件对比度。不要让蓝/紫/灰或任何单一色系铺满整个界面，也不要混用互相冲突的强调色。

- 先完成布局、对齐、字号、间距、内容密度和空状态，再选色和添加效果。
- 页面使用分区、列表、分隔和上下文布局；只有重复实体或确实需要聚焦的交互对象才使用卡片。避免卡片套卡片和仪表盘式卡片墙。
- 阴影要轻且有层级理由；不使用大面积渐变背景、装饰性光球或长时间运行的粒子背景。
- 微动效可用于按钮按下、面板开合、任务状态转换和完成确认。仅在任务确实完成时考虑一次短促、可关闭的庆祝效果；不能干扰继续操作。
- 动画遵循系统减少动态效果设置。优先使用 `transform`/`opacity` 等轻量属性；避免持续重绘、模糊滤镜和大量常驻动画。动效关闭后流程仍完整可用。
- 所有窗口尺寸下检查文字换行、溢出、按钮可达性、焦点状态和面板重排；不能依赖固定 900px 最小宽度来回避布局问题。

## 功能验收门槛

### 模型配置与对话

- 用户能选择明确支持的 Provider，填写模型、端点和密钥；密钥写入受操作系统保护的本地凭据存储，不回显、不写入普通日志或仓库。
- “保存配置”和“测试连接”是不同动作，各自显示真实执行结果。任何 RPC/网络失败都不能显示成功。
- 选择配置后，聊天真实调用该模型并显示模型响应；调用状态、取消、超时、限额/费用未知和错误可见。
- 不进行后台探测或非用户发起的收费请求。测试连接由用户明确点击，并告知它是否会产生费用。

### Agent 任务

- 对话与任务提案语义清楚；提案可编辑，并展示计划、涉及路径、权限、预算/费用边界和验收方式。
- 只有明确批准后才执行受限动作。模型调用和工具调用都受任务预算约束。
- 每个步骤有可观察状态；暂停、恢复、取消在实际工作流生效，完成后呈现产物、验收证据和通知状态。
- 恢复冻结、未知发送、费用未知或权限失败时必须 fail closed；界面不能提供一个无条件清除保护状态的操作。

### 交互与视觉

- 每个可见按钮均实现对应行为；无功能的控件不得伪装成可点击。
- 保存、连接、发送、审批、暂停、恢复、取消、重试、打开产物和查看日志均有加载、成功、失败/不可用反馈。
- 空状态告诉用户当前缺少什么以及唯一合理的下一步；错误提供原因和可行恢复动作。
- 常用键盘操作、清晰焦点、合理目标尺寸、文本缩放、系统减少动态效果和足够对比度均须检查。
- 视觉通过产品负责人和用户的实际操作验收；测试通过、构建通过或一张截图均不能单独代表体验合格。

## 分阶段执行顺序

1. **整理真实基线：** 先检查工作区中其他会话的所有未提交改动和测试结果；保留改动，列清已修复、待修复、未验证事项。继续修复 Code Review 的恢复冻结、delivery intent 与恢复路径测试缺口。
2. **让核心能力真实可用：** 完成模型凭据配置、测试连接、真实模型对话和安全错误处理；由用户在本机输入新的凭据，不复用曾发到聊天中的旧 Key。自动测试覆盖契约，真人手动确认 UI 行为和服务返回。
3. **先给用户看交互设计：** 在大规模改 UI 前，交付导航结构、关键页面线框/文字布局、关键按钮状态和错误/空状态。用户确认后再实施重设计。
4. **完成任务闭环和视觉系统：** 接入模型驱动的任务提案、审批、受限执行、验收、恢复和日志；之后统一主题、组件状态、响应式/窄窗布局、精细排版与克制动效。
5. **手动验收与迭代：** 每个阶段生成可运行构建，给用户准确的点击步骤、预期结果、日志位置和反馈格式。用户手动验收；根据日志和实际体验迭代。未通过的项目明确标为未验收，不推送新的公开版本。

## 参考原则

本标准参考 Apple Human Interface Guidelines 的反馈/动效原则、Material Design 的可访问动效指导、Nielsen Norman Group 的可见状态/用户控制/错误预防启发式，以及 Linear 关于简化层级和减少界面噪声的设计复盘。具体体验仍以本产品的用户任务和手动验收为准。
