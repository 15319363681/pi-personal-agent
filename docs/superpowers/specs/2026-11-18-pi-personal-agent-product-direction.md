# Pi Personal Agent 项目方向与产品边界

日期：2026-11-18

状态：产品方向已由用户确认

适用项目：`D:\Atry`

用途：作为产品负责人和主线开发会话之间的方向交接，指导后续实现、手动验收和迭代。

本文件确认的是产品目标、首版范围、用户体验和开发推进方式。它不代表所有架构提案、Spike 结果、代码或功能已经通过审核或达到生产质量。

## 产品定义

Pi Personal Agent 是一个服务个人工作流的 Windows 桌面 Agent。用户通过自然语言提出问题或工作目标，Agent 可以对话、检索公开资料、处理用户授权的本地文件、执行有边界的多步任务，并把状态、错误和产物清楚地交还给用户。

它必须成为可持续使用、持续迭代的真实产品。首版目标不是展示 Agent 概念的 Demo，也不是先完成一个小样再由用户决定项目是否继续。实现按可运行的纵向功能切片持续推进，直到下文的首版核心流程可以实际使用，再由用户根据黑盒体验、日志和缺陷继续迭代。

## 产品负责人已确认的方向

- **服务对象：** 首版服务一位个人用户，不做团队协作、多租户或通用 Agent 平台。
- **桌面平台：** Windows 11 是首发正式支持平台。当前用户电脑为 Windows 11 专业版 Build 26100；不承诺 Windows 10 首发兼容。
- **Pi 的定位：** Pi Agent 是本产品的 Agent 底座。只复用符合 Personal AI 产品目标的 Pi 能力，不为保留 Pi 的无关功能而改变产品需求，也不把系统抽象成可替换任意 Agent 引擎的平台。
- **Harness 的定位：** 本产品 Harness（当前由桌面 Runtime 承载）负责权限、任务状态、隔离、运行日志和可靠性；Pi 负责 Agent 对话与工具循环。Skills、MCP 和本地插件只能通过 Harness 暴露的受控能力接口工作，不得绕过授权或直接获得宿主完整权限。
- **DeepSeek Harness 的借鉴范围：** 参考其插件管理及 Agent 创建插件的产品流程，不整体照搬其 Runtime、执行内核或权限实现。具体接口仍以本产品单用户桌面边界为准。
- **本地插件生命周期：** 首版推进 Agent 为用户创建、测试和管理本地插件的闭环。创建或更新先形成未启用草稿；测试在受控 Worker 中执行并将开发/测试记录保存在本机；用户查看变更与测试结果并确认后才启用。禁用、更新、删除和失败状态需可见、可恢复或可诊断。Langfuse 用于改进 Harness，不作为插件权限或运行状态的权威来源。
- **插件权限边界：** 普通插件按受限 Worker 方向运行，只能调用 Harness 明确授予的能力；不能因参考 DeepSeek Harness 而继承宿主全部权限。任意第三方插件安装和公开插件市场不属于首版。
- **CowAgent 的定位：** 优先研究并复用用户架构图中 CowAgent 的第一层和第三层能力；中间层由本项目围绕个人使用做精简、清楚的模块边界，并保留后续扩展能力。复用代码或流程前要核实许可证、依赖和运行边界。
- **一个个人助理、多个入口：** 桌面和企业微信服务同一位用户、同一套个人配置、明确保存的个人记忆和任务；不同入口保留各自的聊天记录，避免自动混合上下文。
- **首发渠道：** 企业微信。优先参考 CowAgent 的企业微信智能机器人 API 长连接方式：桌面端主动连接，不依赖公网回调转发服务。首版仅开放用户本人单聊，暂不接群聊。
- **离线行为：** 桌面 Agent 未运行或未连接时，企业微信助理不可用。应用恢复后重连；未验证前不承诺企微离线消息一定补送。
- **模型：** 用户可以配置多个模型服务并切换当前模型，支持常见 API 服务和 OpenAI 兼容的自定义地址。密钥受本机凭据保护；本地兼容模型可由用户配置接入，不要求产品捆绑模型运行时。
- **数据边界：** 本机数据是会话、任务、个人记忆和产物的权威来源。用户明确选择工作目录；个人记忆由用户审核后保存，并可查看、修改和删除。首版提供本地备份、恢复和导出，不做默认云同步。
- **云服务说明：** 使用云模型时，请求所需的对话内容和用户明确提供的资料会发送给选定服务商。产品必须在配置或首次使用时清楚说明数据去向，不得宣称所有数据始终留在本机。
- **对话和任务：** 普通问题作为对话处理。清楚的多步工作请求可直接创建可跟踪任务并开始执行，不再要求一次多余的“开始”确认；目标或授权不明确时先询问。仅在超出现有授权或涉及高影响副作用时暂停并请求确认。
- **外部发送：** Agent 可以自动回复用户在企业微信发起的同一对话。联系新对象、发往其他群聊或计划性主动推送前，必须由用户确认。
- **可见性：** 用户需要看到任务状态、步骤进度、工具结果、产物、失败原因和诊断日志。日志本机保存并默认脱敏。任务完成或等待批准时，即使窗口缩到托盘也应能通知用户。
- **可靠性：** 应用重启后保留任务状态；安全的步骤可以恢复。若外部副作用结果不确定，暂停并交由用户处理，不能自动重复发送。
- **视觉和交互：** 桌面主界面以对话为入口，让任务状态和结果容易查看。支持跟随系统或手动切换浅色/深色主题；色彩协调、信息层级清楚、控件行为可预测。动效和光影只用于层次与反馈，尊重系统减少动态效果设置，不持续消耗资源。
- **语音：** 语音输入、语音输出和实时语音对话不纳入首版，先完成文字、文件和渠道的核心闭环。
- **技能与 MCP：** 首版逐步接入权限受控的 Skills/MCP，并支持用户启用或停用。首版优先交付由产品维护的 Skills、用户授权的 MCP 能力和 Agent 创建本地插件的闭环；公开技能/插件市场及任意第三方插件安装后置。

## 近期实现顺序

以下顺序覆盖此前产品计划中“本地确定性任务演示优先”的安排；已存在的 Runtime、权限、凭据和日志代码继续复用，不要求为此重写桌面壳或重复已通过的 Spike。

1. **Pi 驱动对话与工具循环：** 将当前真实模型请求接入 Pi Agent Core 与 Pi AI；保留已实现的 Provider、safeStorage 和诊断关联 ID。先交付 Harness 控制下的只读工作区工具，让模型能基于工具结果继续回答，并记录工具状态、结果摘要和错误。
2. **受控 Skills 与 MCP：** Skills 和 MCP 工具由 Harness 注册、审核权限并纳入运行日志；工具执行经过既有 PermissionGateway 和受限 Worker。MCP 外部连接、命令和文件范围默认关闭或最小授权，连接/工具结果不伪装成完成。
3. **Agent 创建插件闭环：** Agent 只能在本地插件草稿区创建或更新插件；Harness 在受限 Worker 中运行检查与测试，保存本地测试记录。变更经用户查看并确认后启用，更新再次确认；用户可管理插件启用状态。任意第三方安装与公开市场不纳入此阶段。
4. **扩展个人工作流：** 在前述边界上推进常见文档/图片解析、网页检索来源、持久化多步任务、恢复、企业微信本人单聊、记忆/定时事项和数据维护。每项按可运行纵向切片交付，不以架构研究或静态演示替代。

## 首版必须交付的真实流程

以下是首版产品范围，不代表目前已经实现。每项都要在可运行的 Windows 11 构建中接通真实行为；静态演示、假数据或固定回复不算完成。

1. **首次使用和模型配置：** 用户配置 Provider、模型、端点和密钥；主动测试连接；成功后能真实发起模型对话。错误、超时、限流和费用/用量未知有真实状态和可操作说明。尚未配置企业微信或工作目录时，仍可使用基础桌面对话。
2. **普通对话：** 对话通过当前选定模型真实完成。模型或网络不可用时保留用户输入并显示失败状态，不伪造成功回复。
3. **本地资料工作流：** 用户授权一个或多个工作目录后，Agent 能读取常见文档和图片，至少覆盖 PDF、DOCX、TXT、Markdown 与常见图片格式；能说明使用了哪些资料，并在授权位置生成或更新交付产物。对原文件的覆盖、删除等高影响操作需要确认。
4. **网页调研：** Agent 能搜索公开网页、整理结果并提供来源链接；不能访问或核实的信息要明确标出。搜索服务及其费用、数据边界在实施选型时说明。
5. **可跟踪任务：** 清楚的任务请求形成持久化任务，用户能查看进度、暂停、取消、处理授权请求和查看产物。应用中断后恢复时展示实际状态；不得将模型回答结束直接当作任务验收或外部投递成功。
6. **企业微信单聊：** 用户完成配置后能查看连接状态，在本人单聊中与桌面 Agent 真实收发消息。断线后自动重连并显示状态。源码分析、模拟测试和真实账号投递分别记录，不能互相冒充。
7. **记忆与定时事项：** 用户可审核保存个人记忆，并查看、修改、删除；支持提醒和周期任务。桌面 Agent 离线时不承诺后台执行，状态应显示为未执行或待处理。
8. **诊断和数据维护：** 用户可查看任务错误、关联日志并导出诊断信息；能手动备份、恢复和导出本地数据。密钥、完整提示词和文件内容不得默认写入普通日志。

## 权限和副作用

- 用户明确提出的任务，可以在已授权的工作目录、工具和预算边界内自动完成常规步骤。
- 目标、输入范围或权限不清楚时先询问，不允许 Agent 自行扩大范围。
- 删除或覆盖文件、主动向外部发送、接触新增敏感范围等高影响动作，执行前单独确认。
- 任务审批必须清楚说明动作、目标、权限范围和可能费用；批准只覆盖用户实际看到并确认的范围。实质变更后重新确认。
- 取消、超时、崩溃或断连后，只能报告已确认的结果。结果未知时标记未知并进入待处理，不能宣称已成功、已撤销或安全重发。
- 任何一项安全隔离能力未验证时，关闭受影响的高风险能力或采用受控替代方案，继续完成其他不依赖该能力的产品工作。

## Pi、CowAgent 与现有技术设计的边界

- 以当前桌面应用和 Pi 生态作为实现起点，优先选择能直接减少产品实现工作量的 Pi Agent、模型 Provider、工具和会话能力；不要为尚无用户需求的多内核切换框架增加开发负担。
- Pi 包的使用范围由功能适配、维护性、许可证和真实源码可用性决定。某个 Pi 子包或扩展机制不满足产品需求时，先评估局部适配或替换该能力，不重写已经适用的桌面产品部分。
- CowAgent 的第一层和第三层按用户架构图作为复用候选；中间层围绕单用户桌面 Agent 精简实现。跨 Python/TypeScript 复用时可以移植协议、流程和成熟逻辑，不要求照搬整套 CowAgent。
- 默认沿用现有 Electron/React/TypeScript 桌面工程。只有出现无法通过局部实现解决的明确技术阻塞，才提出更换技术栈。
- `pi-durable` 是否作为权威执行/会话存储、SQLite 事务和 Windows worker 隔离如何落地，属于需以当前实现和证据确认的架构问题。本文件确认产品方向，不等同批准所有既有设计文档中的技术提案、参数或安全声明。

## 开发推进规则

1. **先读现状再动手。** 每个工作会话先检查仓库状态、项目指令、未提交改动、已有实现和测试结果。保留其他会话的改动，不用旧计划或旧版本覆盖它们。
2. **从当前真实产品状态持续向前交付。** 先完成能被用户使用的纵向功能切片，例如模型配置与真实对话，再接入任务执行和资料工作流，再接入企业微信及后续能力。每个切片都应包含界面、运行时、错误处理、日志和验收路径。
3. **Spike 是局部工具，不是项目阶段门。** 只有确实阻塞某个功能、且无法由现有证据解决的问题才新建定向 Spike。Spike 要有明确问题、时间/范围边界和通过标准；验证失败时对该项选安全降级或暂时关闭，再继续其他可交付功能。不得因一个未证实的组件反复停止整个产品开发。
4. **不把计划完成或代码合并等同产品完成。** 记录哪些功能已真实实现、哪些只是源码推断或模拟测试、哪些能由用户现在点击验收、哪些仍未完成。
5. **自动化测试和用户黑盒验收都要有位置。** 代码改动运行适当的自动化检查；交付可运行构建时，同时提供精确的手动点击步骤、预期结果、日志位置和失败时要提供的关联 ID。自动化测试不能替代用户实际操作和体验反馈。
6. **所有可见控件都必须有效。** 每个按钮和入口要有真实行为及加载、成功、失败、禁用状态。尚未实现的功能不以“已可用”的按钮或假流程展示。
7. **禁止无证据的完成声明。** 报告测试命令和实际结果；把源码结论、fake provider 测试、loopback 测试和真实服务/账号验证分开标注。未做真实企业微信投递时，不称渠道闭环已通过。
8. **遵守用户工作方式。** 未经用户明确要求，不使用 Playwright 截图或子智能体。不要把新建 Spike、研究报告或演示原型当作产品交付的替代品。
9. **进度更新保持可操作。** 定期汇报“已实现”“现在可测试”“未完成/受限”“下一项交付”，并用日志和真实运行证据支持结论。

## 产品验收口径

当且仅当下列条件都满足，才可以称为“首版可用”；否则应报告具体完成比例和可测试范围：

- 首次启动能完成模型配置和连接测试，桌面对话是真实模型回复。
- 主界面中的已显示功能都可操作，没有固定文本假装模型能力或按钮空转。
- 用户至少能完成一条真实个人工作流：提问/创建任务、使用授权资料或网页来源、查看过程、收到产物和验收状态。
- 企业微信单聊真实收发在真实账号上完成过一次端到端验证，在线、断线、重连状态可见；如果该集成尚未验证，必须明确标为未验收。
- 任务状态可在重启后解释；不确定的费用或外部副作用不会被自动伪装成成功或重复执行。
- 错误能通过界面与本地脱敏日志定位；用户可以按提供的步骤亲自完成黑盒测试并反馈。
- 用户实际操作后认可主要信息架构、按钮位置和视觉层级。自动测试通过或单张截图不能单独替代此项验收。

## 仍待实现阶段选择的事项

以下是实施选择，不应被误认为用户已经选定具体供应商或承诺已验证：

- 首版内置 Provider 名单及各家 API 能力差异；OpenAI 兼容自定义端点作为扩展路径。
- 网页搜索服务、调用费用、来源质量和失败行为。
- 文档解析、图片理解/OCR 的实现与支持格式细节。
- 企业微信平台实际配置、真实账号投递、重连行为与离线消息补送能力。
- 安装包签名、自动更新和版本发布流程。
- 备份加密、保留数量与磁盘空间阈值等运维数值。

这些事项需要在影响相应切片时以真实资料和测试决定。选择未完成时可以先交付其他独立功能，但不能对未验证的能力做产品承诺。
